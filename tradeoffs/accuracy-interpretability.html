Accuracy vs. interpretability

More flexible models usually predict better but are harder to explain. How much explainability you should give up for accuracy depends on what is at stake when the model is wrong or questioned.

Accuracyvs.Interpretability

The trade-off

A linear model or a short decision tree can be read: you can see which inputs mattered and by how much. Gradient-boosted ensembles and deep networks combine thousands or millions of parameters, which lets them capture subtle patterns, but no one can follow the reasoning for a given prediction. Accuracy usually rises with model flexibility, with diminishing returns, while interpretability falls steadily.

Post-hoc tools (feature importance, SHAP values, surrogate models) give approximate explanations of complex models, which helps but isn't the same as a model that is transparent by construction. What you need depends on the decision: whether people affected can ask "why", whether regulation requires reasons, whether errors are costly, and whether you need to debug and trust the model.

How to use it

  1. Start with a simple, readable baseline. It sets the accuracy bar, and often turns out to be close enough.
  2. Measure what complexity buys. If a boosted model gains one point of accuracy over a tree, ask whether that point is worth the loss of explanation.
  3. Match the model to the stakes. Lending, hiring, medicine and the justice system call for explanations, while ranking or recommendations rarely do.
  4. If you choose a complex model, plan the explanations, monitoring and a human review path from the start.

Example

A bank compares a deep model with a scorecard built from a few dozen features. The deep model approves loans slightly more accurately, but a rejected applicant is legally entitled to reasons, and auditors need to check for bias. The bank uses the scorecard (with simple monotonic rules) for decisions. A marketing team picks which offer to show a visitor, where no one asks for reasons and a wrong guess costs little, and uses the most accurate model it can train.

Watch out for

  • Interpretable isn't automatically correct. A readable model can still encode bias or rely on a spurious feature. Readability makes the problem easier to find.
  • The gap is often smaller than expected. On tabular data, simple models are frequently close to complex ones. On images and text, the gap can be large.
  • Related: bias vs. variance is about generalising to new data, whereas this is about explaining the predictions. Flexibility vs. simplicity describes the same pull in software design.
